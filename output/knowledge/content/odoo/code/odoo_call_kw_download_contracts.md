Observed Odoo RPC and download contracts worth normalizing in PoC helpers:

- JSON-RPC calls use the standard envelope `{"jsonrpc":"2.0","method":"call","params":...}` and are commonly sent to `/web/dataset/call_kw/<model>/<method>`.
- `POST /web/session/authenticate` is also a JSON-RPC route; its `result` already includes `user_context`, which can be reused as the default `kwargs.context` for later `call_kw` requests.
- If a helper wants to confirm the authenticated identity or capture richer audit data, `/web/session/get_session_info` should be called as a JSON route with `POST` and payload `{"jsonrpc":"2.0","method":"call","params":{}}`, not treated as a plain GET endpoint.
- `search_read` requests can use `args: [[]]` with field selection in `kwargs.fields`.
- `create` results are easiest to handle defensively: normalize either a scalar id or a one-element id list before passing the value to later calls.
- Odoo may signal a logical failure under an `error` key even when the HTTP request itself succeeded, so save the body and handle that path separately.
- File-generating actions commonly return metadata with a `/web/content` download URL instead of returning file bytes inline, so callers need a second authenticated GET.
- A common wizard implementation pattern is a `TransientModel` that writes generated bytes into a `fields.Binary` field plus a `fields.Char` filename field on the wizard record itself, then returns an `ir.actions.act_url` dict whose `url` looks like `/web/content/?model=<wizard_model>&id=<wizard_id>&field=<binary_field>&filename_field=<filename_field>&download=true`.
- When a `call_kw` action returns `{"type": "ir.actions.act_url", ...}`, treat that response as a second-stage download contract: preserve the authenticated session cookie, extract `result["url"]`, and fetch that URL separately.
